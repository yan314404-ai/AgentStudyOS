fix: 修复 Phase 7 三个边界 bug（会话状态机 + 评测静默兜底）

用 edge_probe.py 对 Phase 7 新代码做边界压力测试，查出 3 个真实缺陷：

1. set_pending() 不校验会话状态：对 status=closed 的会话仍能写 pending，
   close() 形同虚设，用户刷新页面会看到「在问一个已关掉的会话」的追问。
   → set_pending/add_turn 都先校验会话存在且非 closed，否则抛 BadRequest。

2. eval_runner.run_eval() 静默过滤未知 kind：把 ("run",) 敲成 ("runs",) 时
   会静默兜底跑一轮零成本用例并返回 100%，看起来「真实运行也过了」，实际
   根本没跑。更糟的是 test_unknown_kind_falls_back_to_cheap 把这个错误行为
   当成期望行为断言了。
   → 未知 kind 直接 raise ValueError；测试改为断言抛错。

3. create() 重复 conv_id 抛 sqlite3.IntegrityError → 500（前端「新会话」
   双击、重试、外部调用都可能撞同一 id）。
   → create() 幂等（已存在直接返回原会话），并捕 IntegrityError 兜底并发。

附带：get_or_create() 遇到 closed 会话改为开新会话而不是复用（否则 close 只
是改了个没人看的字段）；router 新增 _conv_write() 统一把 cvs.BadRequest 翻成
400（原来会漏成 500）。

测试：test_intent.py +4 用例，test_eval.py 改 1 个；210/210 全过（206+4），
真实库 mtime 未变。真实库 8000 端口复验：未知 kind→400 带中文提示、重复
conv_id→200 返回同一会话、close 后 chat→开新会话并追问、正常评测 17/17。
